## Project Overview

**ThreadMyMail (Millo)** is an Android APK — a self-contained AI email agent harness that runs entirely on your phone. Your credentials (IMAP/SMTP + app password) and AI key (BYOK) never leave the device. No OAuth, no backend, no subscription.

The mobile app is the product. The frontend directory contains a landing/download page (React + Vite + Tailwind).

```bash
# Install dependencies (always use expo install for SDK-compatible versions)
npx expo install <package>

# Start dev server
npx expo start

# Run on Android device/emulator (development build — required for react-native-mail-engine)

npx expo lint

# Diagnose dependency/config issues
npx expo-doctor

npx expo install --fix

# Release build (unsigned — fine for local testing)
npx expo prebuild --platform android --clean
cd android && ./gradlew assembleRelease
# APK at: android/app/build/outputs/apk/release/app-release.apk

# Release build (signed, CI)

# Trigger workflow_dispatch with optional release_tag and abi inputs
```

### CI / GitHub Actions

The workflow at `.github/workflows/android-build.yml`:
- Runs on push to `main` (paths: `mobile-app/**`, workflow file)
- Supports `workflow_dispatch` with `release_tag` and `abi` inputs
- Generates signed APK when keystore secrets are set
- Publishes GitHub Release with APK when `release_tag` provided

## Architecture (Mobile App)

### Core Data Flow

1. **Onboarding** (`Onboarding.tsx`) — Connect email (IMAP/SMTP + app password), add AI provider (BYOK), pick skills → persists to SecureStore
2. **AppShell** — Reads onboarding flag + account from SecureStore; if configured, auto-starts `MailSync`
3. **MailSync** (`mailSync.ts`) — Sync engine:
   - Imports last 180 days of headers in bounded batches (50/batch, max 12 batches = 600 messages/run)
   - Stores only headers + previews in SQLite (`mailStore.ts`) — never full MIME bodies
   - Starts IMAP IDLE for realtime push
   - Enforces 5,000 message cache cap (evicts oldest)
4. **MailBridge** (`mailBridge.ts`) — Seam over `react-native-mail-engine` (Nitro native module). Lazy-loaded so app boots in Expo Go.
5. **Screens** subscribe to `MailSync` singleton (`mailSyncSingleton.ts`) for live sync state + messages.

### Storage

| Data | Store | Notes |
|------|-------|-------|
| Email credentials (IMAP/SMTP + app password) | `expo-secure-store` (Android Keystore) | `accountStore.ts` |
| AI provider keys (BYOK) | `expo-secure-store` | `providerStore.ts` |
| Onboarding flag | `expo-secure-store` | `prefs.ts` |
| Cached message headers/previews | `expo-sqlite` (WAL mode) | `mailStore.ts` — capped at 5,000 |
| Message bodies | Never cached — fetched on demand | |

### Native Module: `react-native-mail-engine`

- Nitro module (C++/JNI) — cannot run in Expo Go
- Requires development build: `npx expo run:android`
- Postinstall patch (`scripts/patch-mail-engine.js`) fixes reserved keyword `inline` in generated C++ headers
- Config plugins handle:
  - Release signing injection (`withAndroidReleaseSigning.js`)
  - JavaMail META-INF deduplication (`withAndroidPackagingPickFirsts.js`)

## Design System

Tokens in `src/theme/theme.ts` — **never hardcode hex values in components**.

- **Palette**: Dark-first (bg `#0B1326`, primary `#7C3AED` violet, accent `#0891B2` cyan)
- **Typography**: Inter 300–700, single-family precision system
- **Touch targets**: ≥48dp minimum, 8dp gaps
- **Motion**: 150–300ms, reduced-motion respected

Shared UI primitives in `src/components/ui.tsx`: Button, Card, SectionLabel, EmptyState, ConfirmDialog, Toast.

## Common Development Patterns

### Adding a new screen
1. Create `src/screens/NewScreen.tsx`
2. Add to `AppShell.tsx` tab bar (`BottomTabBar.tsx` + `TopBar.tsx` if needed)
3. Follow existing screen patterns: subscribe to `MailSync` singleton, use theme tokens

### Adding a new provider preset
Edit `src/lib/providers.ts` — add to `PROVIDER_PRESETS` array with `id`, `label`, `baseUrl`, `defaultModel`, `keyHint`

### Modifying sync behavior
Edit `mailSync.ts` constants: `HISTORY_DAYS`, `IMPORT_BATCH_SIZE`, `MAX_IMPORT_BATCHES`, `MAX_CACHED_MESSAGES` (also in `mail.ts`)

### Adding a new secure setting
Follow `accountStore.ts` / `providerStore.ts` / `prefs.ts` pattern: use `expo-secure-store` with versioned keys (`threadmymail.xxx.v1`)
